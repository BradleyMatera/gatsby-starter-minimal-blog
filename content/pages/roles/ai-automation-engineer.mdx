## Core Responsibilities

An AI & Automation Engineer is responsible for building, integrating, and maintaining automated workflows and AI-powered features. Key responsibilities include:

- **LLM integration:** Connecting applications to large language model APIs ([OpenAI](https://platform.openai.com/docs), [Anthropic](https://docs.anthropic.com/)) for chat, summarization, and extraction tasks.
- **Agent workflow design:** Orchestrating multi-step AI agent pipelines using frameworks like [LangChain](https://python.langchain.com/docs/get_started/introduction) for tool use, retrieval, and reasoning chains.
- **Local model hosting:** Running open-weight models locally with [Ollama](https://ollama.com/) for development and prototyping without external API costs.
- **Backend service development:** Building REST APIs with [FastAPI](https://fastapi.tiangolo.com/) to serve AI endpoints with typed validation and automatic OpenAPI docs.
- **Prompt engineering and documentation:** Treating prompts as versioned engineering artifacts with documented inputs, expected outputs, and manual review checkpoints.
- **Evaluation and safety:** Designing evaluation workflows to detect hallucinations, measure output quality, and enforce safety guardrails before features reach users.
- **Automation scripting:** Writing Python and Node.js scripts to automate content pipelines, data processing, and repetitive development tasks.

## Expanded Process Notes

### How I approach an AI automation project

1. **Define the problem in plain language** — Write down what the automation or AI feature should accomplish and what a successful output looks like.
2. **Choose local vs. API** — For prototyping, I use [Ollama](https://ollama.com/) to run models locally for zero-cost iteration. For quality-critical outputs, I test against [OpenAI](https://platform.openai.com/docs) or [Anthropic](https://docs.anthropic.com/) APIs.
3. **Build the backend scaffold** — I use [FastAPI](https://fastapi.tiangolo.com/) because it provides automatic request validation, typed responses, and generated OpenAPI documentation ([Source](https://fastapi.tiangolo.com/features/)).
4. **Document prompts as artifacts** — Each prompt is stored with its version, inputs, expected output, and manual review notes in the repository README.
5. **Add evaluation checkpoints** — Before shipping, I run manual evaluation passes to check for hallucinations, off-topic responses, and format violations.
6. **Disclose AI assistance** — Any code drafted by AI tools is labeled in the README with the prompt used and the edits I made manually.

### Common pitfalls I have encountered

- **Hallucinated API calls:** LLMs sometimes generate plausible-looking but non-existent library functions. Manual review of generated code is mandatory ([Source](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)).
- **Cold start latency:** Free-tier hosting (e.g., Render) can take several minutes to wake up, which breaks chat workflows. Documenting this in the README sets correct expectations.
- **Token cost surprises:** Without explicit token limits, long conversations can exceed free-tier API quotas. Setting `max_tokens` and truncating context is essential ([Source](https://platform.openai.com/docs/api-reference/chat)).
