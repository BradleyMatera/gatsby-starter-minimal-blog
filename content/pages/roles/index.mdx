## What engineering roles do I practice?

I practice five engineering roles: cloud engineer, DevOps engineer, backend engineer, full-stack engineer, and AI automation engineer. Each role page includes real projects, verified skills, and honest scope notes about where I still need mentorship. These are practice reps, not claimed professional titles. Every claim links to a real demo, repo, or blog post so expectations stay realistic and transparent.

The five roles I practice, side by side:

| Role | Core focus | Key tools | Current proof | Gaps I am working on |
|------|-----------|-----------|--------------|---------------------|
| Cloud Engineer | AWS services, serverless, cost modeling | [Lambda](https://docs.aws.amazon.com/lambda/latest/dg/welcome.html), [DynamoDB](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Introduction.html), [S3](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html) | Deployed serverless pipeline, cost write-ups | Production ownership at scale |
| DevOps Engineer | CI/CD, containers, deployment automation | [GitHub Actions](https://docs.github.com/en/actions), [Docker](https://docs.docker.com/) | Build checks, deployment workflows | Large-team CI/CD with shared observability |
| Backend Engineer | APIs, auth, persistence | [Node.js](https://nodejs.org/en/docs), [FastAPI](https://fastapi.tiangolo.com/) | Auth and API experiments | Enterprise-scale system design |
| Full-Stack Engineer | End-to-end application flow | [React](https://react.dev/), Node.js, databases | Full-stack deployed projects | Production traffic and business impact |
| AI / Automation Engineer | Local models, prompt orchestration, automation | [FastAPI](https://fastapi.tiangolo.com/), local LLMs | Small automation tools and workflows | Production ML pipeline ownership |

## How do I show proof of skills for different engineering roles?

Each role page is proof-based, meaning every skill claim links to a real demo, repository, or blog post. The pages are transparent about gaps like production ownership, large-scale operations, and incident response. Instead of collecting titles, the focus is on showing what I actually practice, what I can point to, and where I still need guidance from experienced engineers.

How proof is structured on each role page:

- **Skills section** — each skill listed links to a specific repo, demo, or write-up that demonstrates it
- **Projects section** — real deployments or experiments with links to live URLs or GitHub repos ([GitHub profile](https://github.com/BradleyMatera))
- **Scope notes** — an honest statement of what I have and have not done professionally
- **Limitations** — explicit callouts of areas where I still need mentorship or production experience
- **Certifications** — links to verified badges where applicable ([AWS certifications on Credly](https://www.credly.com/users/bradley-matera))
