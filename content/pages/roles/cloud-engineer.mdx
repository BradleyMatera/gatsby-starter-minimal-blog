## Core Responsibilities

A Cloud Engineer is responsible for designing, deploying, and maintaining cloud infrastructure and services. Key responsibilities include:

- **Cloud architecture:** Designing scalable, cost-effective infrastructure on [AWS](https://docs.aws.amazon.com/) using services like Lambda, S3, DynamoDB, and API Gateway ([Source](https://docs.aws.amazon.com/whitepapers/latest/aws-overview/introduction.html)).
- **Infrastructure as Code (IaC):** Provisioning resources with [Terraform](https://developer.hashicorp.com/terraform/docs) or AWS CloudFormation instead of manual console clicks ([Source](https://developer.hashicorp.com/terraform/intro)).
- **Cost management:** Monitoring cloud spend, setting budgets and billing alerts with [AWS Budgets](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-managing-costs.html), and optimizing free-tier usage.
- **Security and IAM:** Designing least-privilege [IAM policies](https://docs.aws.amazon.com/IAM/latest/UserGuide/introduction.html), using [IAM Access Analyzer](https://docs.aws.amazon.com/IAM/latest/UserGuide/what-is-access-analyzer.html) to find unintended access, and reviewing security groups.
- **Monitoring and alerting:** Setting up [CloudWatch](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/WhatIsCloudWatch.html) dashboards, log groups, and [SNS](https://docs.aws.amazon.com/sns/latest/dg/welcome.html) alerts for operational visibility.
- **Serverless development:** Building event-driven workflows with [AWS Lambda](https://docs.aws.amazon.com/lambda/latest/dg/welcome.html) triggered by S3 events, API Gateway, or EventBridge.
- **Deployment and CI/CD:** Using [GitHub Actions](https://docs.github.com/en/actions) for build validation and deploying static sites to [GitHub Pages](https://docs.github.com/en/pages) or services to [Render](https://render.com/docs).

## Expanded Process Notes

### How I approach a cloud deployment

1. **Map the architecture** — Draw out which AWS services are needed (e.g., S3 for storage, Lambda for compute, DynamoDB for state) and how data flows between them. The [AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html) provides the design principles I reference.
2. **Estimate costs upfront** — Before building, I document expected costs per request using AWS pricing pages ([Lambda pricing](https://aws.amazon.com/lambda/pricing/), [S3 pricing](https://aws.amazon.com/s3/pricing/)). This was a core part of my internship capstone.
3. **Set up IAM with least privilege** — Each service gets its own role with only the permissions it needs. [IAM Access Analyzer](https://docs.aws.amazon.com/IAM/latest/UserGuide/what-is-access-analyzer.html) helps identify over-permissive policies.
4. **Build serverless workflows** — For event-driven tasks, I use Lambda functions triggered by S3 events ([Source](https://docs.aws.amazon.com/lambda/latest/dg/with-s3.html)). My capstone project used this pattern for metadata extraction.
5. **Add monitoring from day one** — CloudWatch dashboards and SNS alerts are configured before the workflow goes live so failures are visible immediately ([Source](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/WhatIsCloudWatch.html)).
6. **Document everything** — Every deployment includes README notes about limitations, free-tier caveats, and what would need to change for production scale.

### Common pitfalls I have encountered

- **Free-tier cold starts:** Render's free tier and AWS Lambda cold starts can introduce latency. This is documented in every project README.
- **Accidental charges:** Without billing alerts, it is easy to incur unexpected costs. I always set up [AWS Budgets](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-managing-costs.html) before deploying anything.
- **Over-permissive IAM:** Default policies that use `*` actions or resources are a security risk. The principle of least privilege is documented in the [IAM best practices guide](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html).
