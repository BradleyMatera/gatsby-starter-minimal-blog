<Section id="overview" eyebrow="Problem" title="User need">
  <p>
    I wanted to learn how to combine Next.js App Router with static export (<code>output: "export"</code>) for GitHub Pages. A Pokédex was a good fit — fixed dataset (151 Pokémon), public API, and enough complexity to exercise build-time data fetching, prerendered detail pages, and client-side search.
  </p>
</Section>

<Section id="approach" eyebrow="Solution" title="What I built">
  <p>
    A Next.js 16 app that fetches PokéAPI data at build time and exports a static site to GitHub Pages. The list view uses client-side search and filtering via <code>PokemonProvider</code> and <code>ItemProvider</code> context. Each Pokémon has a prerendered detail page with sprites, stats, moves (first 10), evolution chains, and item interactions — no runtime API calls needed on navigation.
  </p>
  <div className="grid-two">
    <Card>
      <h3 className="feature-card__title">User interface</h3>
      <ul className="feature-list">
        <li>Home page lists 151 Pokémon with search and pagination</li>
        <li>Search page filters the in-memory list</li>
        <li>Item Dex lists items with search and pagination</li>
        <li>Detail pages show sprites, stats, moves, evolutions</li>
        <li>Light/dark theme toggle</li>
        <li>Tailwind CSS v4 + NextUI components</li>
      </ul>
    </Card>
    <Card>
      <h3 className="feature-card__title">Technical implementation</h3>
      <ul className="feature-list">
        <li>Next.js 16 App Router with <code>output: "export"</code></li>
        <li><code>generateStaticParams</code> enumerates 151 names at build time</li>
        <li><code>fetchPokemonDetails</code> runs per name — sprites, species, evolutions, moves</li>
        <li>Trailing slashes for GitHub Pages static layout</li>
        <li>Image optimization disabled (<code>unoptimized: true</code>) for static export</li>
        <li>GitHub Actions workflow publishes <code>out/</code> to Pages on push to main</li>
      </ul>
